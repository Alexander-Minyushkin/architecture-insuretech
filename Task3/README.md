# Анализ текущей архитектуры

ins-product-aggregator сейчас даёт синхронные ответы и для этого вынужден опрашивать несколько внеших сервисов.
В ближайшее время InsureTech планирует подписать агентское соглашение ещё с пятью страховыми компаниями. 
Это вызовет увеличение количество опрашиваемых сервисов, увеличит время работы и повысит вероятность ошибок.

Эту часть взаимодействия нужно сделать асинхронной

Так как команда решила хранить локальные реплики данных о продуктах и тарифах в сервисах core-app и ins-comp-settlement, нам **нужно реализовать паттерн Transactional Outbox** для повышения надёжности решения.

ins-product-aggregator будет периодически сам опрашивать внешние системы и писать обновления в core-app через очередь, эти обновления будут сохраняться в Outbox на стороне core-db и отправляться через очередь в ins-comp-settlement-db.
